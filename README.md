# Виш-лист

Сайт со списком подарков ко дню рождения. Друзья открывают ссылку, выбирают подарок
и бронируют его — целиком или в складчину, — чтобы никто не подарил одно и то же.

**Прод:** https://wishlist.dimadomore.com
**Админка:** https://wishlist.dimadomore.com/admin?key=КЛЮЧ (ключ — в `.dev.vars` и в секретах Worker)

## Как добавить или изменить подарок

Всё живёт в [`products.json`](products.json). Открыл, поправил, запушил в `main` — сайт обновился.

```jsonc
{
  "id": "bellroy-coin-wallet",     // ключ, к нему привязаны брони — НЕ менять у товара, который уже могли забронировать
  "title": "Bellroy Coin Wallet",
  "brand": "Bellroy",
  "category": "Кошельки",          // просто подпись на карточке, фильтров по категориям нет
  "description": "…",              // текст на странице подарка
  "url": "https://…",              // null → карточка без кнопки «В магазин»
  "image": "/images/bellroy-coin.jpg",
  "sourceImage": "https://…",      // откуда скачана картинка, только для справки
  "priceMdl": 2180,                // null → цена не показывается
  "priceEur": 109,
  "hidden": false                  // true → временно спрятать, не удаляя
}
```

Порядок объектов в массиве `items` = порядок карточек на сайте.

**Новая картинка:** положи файл в `public/images/` и пропиши путь в `image`. Чтобы её потом
можно было перекачать с оригинала, допиши строку в [`scripts/fetch-images.sh`](scripts/fetch-images.sh)
и запусти `bash scripts/fetch-images.sh`.

**Цены** пересчитаны по курсу на 2026-08-18 (USD→MDL 17.271, EUR→MDL 20.018, USD→EUR 0.8631) —
курс записан в `products.json` в поле `rates`. Живого курса нет и не нужно.

## Как это работает

- **Фронтенд** — Vite + vanilla TypeScript, без фреймворков. Товары попадают в бандл из `products.json` на этапе сборки.
- **Бэкенд** — один Cloudflare Worker: раздаёт статику и обслуживает `/api/*`.
- **База** — Cloudflare D1 (SQLite). Хранит только брони: подарок, имя, режим, время.

Правила бронирования (проверяются на сервере одним SQL-запросом, поэтому две
одновременные брони не могут пролезть обе):

- свободный подарок можно либо **подарить целиком**, либо **начать складчину**;
- если складчина уже началась — «подарить целиком» пропадает, можно только присоединиться;
- если подарок дарят целиком — он закрыт для всех;
- одно имя не может занять один подарок дважды (регистр и пробелы не важны);
- снять бронь может кто угодно — это список для друзей, а не банковский сейф.

## Разработка

```bash
npm install
npm run dev          # wrangler dev на http://localhost:8787 (фронт + API + локальная база)
```

Первый запуск: создать локальную базу и ключ админки.

```bash
npm run db:local
echo 'ADMIN_KEY="любая-строка"' > .dev.vars
```

Полезное:

| Команда | Что делает |
|---|---|
| `npm run dev` | локально: сайт + API + локальная D1 |
| `npm run build` | сборка фронта в `dist/` |
| `npm run deploy` | сборка + выкатка на Cloudflare |
| `npm run db:local` | накатить схему на локальную базу |
| `npm run db:remote` | накатить схему на боевую базу |
| `npm run typecheck` | проверка типов |

## Деплой

Пуш в `main` выкатывает сайт автоматически. Вручную — `npm run deploy`.

Ключ админки задаётся отдельно и в репозиторий не попадает:

```bash
npx wrangler secret put ADMIN_KEY
```

Посмотреть или почистить брони можно на `/admin?key=…` или прямо в базе:

```bash
npx wrangler d1 execute wishlist-db --remote --command "SELECT * FROM bookings"
```
