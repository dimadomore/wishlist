# Wishlist — план проекта

> Личный виш-лист ко дню рождения Димы. Друзья открывают сайт, смотрят товары и бронируют
> подарки (целиком или в складчину), чтобы не дублироваться. Референс дизайна —
> https://www.curated.supply/ (детальный разбор: [docs/design-reference.md](docs/design-reference.md)).
>
> Документ самодостаточен: по нему можно работать без исходного чата.

## 1. Ключевые решения (утверждены)

| Вопрос | Решение |
|---|---|
| Хостинг | Cloudflare: статика + Worker API + база **D1** (serverless SQLite) |
| Домен | `wishlist.dimadomore.com` (домен `dimadomore.com` уже в Cloudflare) |
| Фронтенд | **Vite + vanilla TypeScript**, без фреймворков |
| Управление товарами | один файл `products.json` — правится руками из кода |
| Видимость броней | имена бронирующих видят **все посетители** |
| Отмена брони | да, на честном слове: нажал на своё имя → убрать. Без авторизации |
| Складчина | у **каждого** товара обе опции: «выкуплю целиком» или «скинусь» (детали в §3) |
| Валюты | цены показываем в **MDL и EUR**, курс зафиксирован (§5), живой курс не нужен |
| Язык | русский, одна версия |
| Hero | без шапки/категорий: один hero-заголовок + список товаров. Текст — временный placeholder, Дима заменит позже |
| GitHub | **публичный** репозиторий `dimadomore/wishlist` |
| Деплой | автодеплой: push в `main` → Cloudflare собирает и выкатывает |
| Админка | скрытая страница по секретному пути — посмотреть/почистить все брони |

## 2. UX

- Одна страница: hero (заголовок + 1–2 строки пояснения «забронируй, чтобы не задублироваться, или скинься с кем-то») → грид карточек товаров.
- Карточка: фото на белом, название, «Brand · Категория»-строка (или короткое описание), цена в двух валютах моноширинным шрифтом, статус брони, кружок-стрелка ↗ на магазин (если есть ссылка).
- Клик по карточке → страница/модалка товара (как на референсе: большая картинка, описание, цена, кнопка на магазин) + блок бронирования.
- Блок бронирования: видно текущее состояние (свободно / «скидываются: Максим, Ира» / «выкуплено: Олег»), поле «твоё имя» и две кнопки: **«Выкуплю целиком»** и **«Скинусь»**.
- Отмена: рядом с каждым именем крестик — любой может удалить (по факту удаляют своё).
- Товары без ссылки на магазин (AeroPress, кофе, палатка) — без стрелки ↗ и без цены (цену можно добавить позже в `products.json`).

## 3. Логика бронирования

Состояния товара:

1. **Свободен** — доступны обе кнопки.
2. **Складчина открыта** (≥1 участник «скинусь») — кнопка «Скинусь» доступна (участников без лимита); кнопка «Выкуплю целиком» **скрывается** — нельзя перебить чужую складчину.
3. **Выкуплен целиком** — обе кнопки скрыты, карточка визуально «занята» (пометка + приглушение), из грида не убирается.

Отмена возвращает товар в предыдущее состояние (удалил единственного участника складчины → снова свободен).

## 4. Архитектура

```
wishlist/
├── PLAN.md
├── docs/                       # исследования (дизайн, товары)
├── public/
│   └── images/                 # фото товаров, скачанные локально (не хотлинки!)
├── src/                        # фронтенд: Vite + vanilla TS
│   ├── main.ts                 # рендер списка из products.json + API-статусы броней
│   ├── product.ts              # вид товара (модалка или #/route)
│   └── styles.css              # токены из docs/design-reference.md
├── products.json               # ЕДИНЫЙ файл управления товарами
├── worker/
│   └── index.ts                # Cloudflare Worker: API + раздача статики (assets)
├── schema.sql                  # D1-схема
└── wrangler.toml               # конфиг: D1 binding, assets, домен
```

- **Один Worker** (Workers + static assets, без Pages) — проще: один `wrangler.toml`, один деплой, кастомный домен `wishlist.dimadomore.com` привязывается прямо к Worker.
- Картинки скачиваем в `public/images/` на этапе сборки проекта (source-URL остаются в `products.json` для справки) — иначе сайт зависит от чужих CDN.

### API (Worker, D1)

```
GET  /api/bookings              → { [productId]: { mode: "full"|"split", names: string[] } }
POST /api/bookings              { productId, name, mode: "full" | "split" }
DELETE /api/bookings            { productId, name }
GET  /api/admin/:secret         → всё + возможность удаления (админ-страница)
```

Валидация в Worker: имя 1–40 символов; нельзя «full», если уже есть участники; нельзя дублировать имя в одной складчине. Race conditions решает D1 (INSERT + проверка в одной транзакции).

### D1-схема

```sql
CREATE TABLE bookings (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  product_id TEXT NOT NULL,
  name TEXT NOT NULL,
  mode TEXT NOT NULL CHECK (mode IN ('full','split')),
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE UNIQUE INDEX idx_unique_name ON bookings(product_id, name);
```

### Формат `products.json`

```jsonc
{
  "id": "xbloom-studio",            // slug, стабильный ключ для броней
  "title": "xBloom Studio",
  "brand": "xBloom",
  "category": "Кофе",
  "description": "Умная пуровер-кофемашина со встроенной кофемолкой…",
  "url": "https://www.curated.supply/products/…",   // null, если без ссылки
  "image": "/images/xbloom.png",
  "sourceImage": "https://framerusercontent.com/…", // откуда скачали, для справки
  "priceMdl": 10350,                 // null, если цену не показываем
  "priceEur": 517,
  "hidden": false                    // быстро спрятать товар, не удаляя
}
```

Порядок в файле = порядок на сайте. Добавить/удалить/править товар = править этот файл и запушить.

## 6. Дизайн (кратко; полностью — docs/design-reference.md)

- Гамма: фон `#f2f2f2`, карточки `#ffffff` без границ и теней, текст `#141414` / `#737373`. Акцент — чёрный, других цветов нет.
- Шрифты: **Geist** (UI/заголовки), **Geist Mono** (цены) — бесплатные, self-host через `@fontsource` или npm `geist`.
- Карточки: radius 16px, квадратная картинка `object-fit: contain`, грид `repeat(auto-fill, minmax(340px,1fr))`, gap 16px, контейнер 1400px.
- Всё интерактивное — «пилюли» (radius 28–48px); кнопка-CTA чёрная с белым текстом; внешние ссылки — кружок 36px `#f5f5f5` со стрелкой ↗.
- Ховеры сдержанные: картинка сползает на 3px, цвета gray→black за 0.4s. Без uppercase.
- Статус брони на карточке: в стиле сайта — маленький текст 14px с цветной точкой (зелёная — свободно, серая — складчина, чёрная — выкуплено).

## 7. Этапы работы

1. **Скелет**: git init, Vite + TS, структура папок, wrangler.toml, схема D1. Первый коммит → создать репо `dimadomore/wishlist` (public) → push.
2. **Данные**: `products.json` из §5, скачать все картинки в `public/images/` (проверить каждую), Thorne — вручную.
3. **Фронтенд**: стили-токены, hero, грид карточек, вид товара, блок бронирования (fetch к API, optimistic UI).
4. **Worker + D1**: API из §4, локальная разработка через `wrangler dev` (миграция схемы локально и на проде).
5. **Админка**: `/admin?key=<секрет>` — список всех броней, удаление.
6. **Деплой**: `wrangler login` (нужно подтверждение Димы в браузере, один раз) → создать D1 базу → deploy → привязать `wishlist.dimadomore.com` → настроить автодеплой из GitHub (Workers Builds).
7. **Проверка**: пройтись по сайту в браузере (desktop + mobile viewport), протестировать бронь/складчину/отмену/гонки, отдать ссылку Диме.
